一、总评

RadioDroid 的 UI 设计系统成熟度远高于一般 fork 项目：统一的设计令牌（间距 / 圆角 / 字阶）、颜色角色化、8 套配色预设 + 亮暗双主题对比度调校，均有据可循且执行一致。主要短板不在「风格」，而在状态设计（空态 / 错误 / 占位几乎缺席，最典型为未播放时的空白封面页）、可发现性（操作图标无文字标签）、个别对比度细节与遗留色彩清理。

二、界面优点

  • 完整的设计令牌体系 — dimens.xml 以 4dp 基准统管间距、4 档圆角、7 级字阶 + display 大数字；布局不再散写 dp/sp，全局一致性有制度保障。
  • 颜色角色化 + 8 套预设 — 每套预设仅「主色 + 强调色」两个槽位，其余全部派生；换肤成本极低且不会出现配色漂移（attrs_theme.xml + ThemePreset.* 覆盖式叠加）。
  • 三层表面体系清晰 — 窗口 #121214 < 卡片 #1E1E20 < 弹层 #26262A（暗色），列表卡片、底栏、对话框的浮起层次一眼可辨。
  • 文字三层色 + 双主题对比度调校 — Primary / Secondary / Tertiary 分工明确；电台备注强调色、失效/删除底色、状态点绿均按两主题分别调值（备注文字 ≥ 4.5:1）。
  • 触摸目标规范 — touch_target_min 48dp，工具栏按钮统一 ToolbarActionButton 最小宽度。
  • 无图标电台动态占位色板 — Material 500 系 7 色轮转，网格 / 列表在缺图场景下依旧活泼有序，是很多同类应用做不到的细节。
  • 「正在播放」高亮与备注锚点有品牌记忆点 — 直角 2dp 描边方框 + 约 31% 同色遮盖、备注「图标 + 强调色文字」一体化，识别性强。
  • 设置页信息架构清楚 — 13 个分类平铺 + 顶部搜索，分组标题走 Label 字阶 + 强调色，扫读效率高。

三、问题清单

P0 · 可用性（建议立即处理）

P0-1播放器两组 Tab 未选中态对比度过低，几乎不可读

全屏播放器顶部「专辑封面 / 信息」与中部「本台曲目 / 曲目历史 / 录音」的未选中项文字压在深色表面上，暗色主题下目测对比度 < 2:1（WCAG 底线 4.5:1），新用户难以发现还有其他页签。代码根源已核实：两组页签均为 ViewPager1 自带的 PagerTabStrip（layout_player_full.xml #L100、#L261），其未选中文字色取框架 textColorSecondary，主主题未定制该值，在当前主题组合下解析出过暗的颜色；该老组件也无法像 TabLayout 那样用 XML 属性定制页签文字色。

建议：首选将两组 PagerTabStrip 替换为 TabLayout（未选中文字 ?attr/colorTextSecondary，暗色 #A8A8A8 对比度约 7:1，选中态强调色 + 短下划线，与电台主页子页签一致）；若暂不替换，可在代码中对 PagerTabStrip 显式 setTextColor + setNonPrimaryAlpha 修正。

P0-2未播放时封面页整页空白（真机复现，根因已定位，降级 P1）

定性确认：占位与加载链路本身完全正常——点击播放后封面立即加载（KIIS 图标秒出）。真正的缺口在未播放状态：FragmentPlayerFull.updateAlbumArt()（#L914-918）开头 PlayerServiceUtil.getCurrentStation() 为 null（未在播）时直接 return，封面 ImageView 保持 XML 初始空态，无任何占位；而同屏的电台标题、顶栏图标、曲目历史均用 Utils.getCurrentOrLastStation()（取最后播放电台）照常显示——同一屏「有信息、无封面」，行为不一致。此发现来自用户观察「封面播放时才出现」，真机复现完全吻合。

建议：① station == null 时回退 getCurrentOrLastStation() 加载最后播放电台的图标（与标题 / 历史行为对齐，改动一行）；② 或为未播放态设计「暂无播放」空态（矢量唱片纹样 + 文案，见概念图 B），避免整页深色空白。

P0-3收藏列表三态视图缺失（当日整页空白未能复现，降级 P2）

「列表无 loading / error / empty 状态视图」属实：无论将来再遇到数据为空还是装载异常，用户都只会看到静默空白。但审查当日踩中的整页空白异常，真机 5 个场景均未复现：冷启动连拍、快速切换页签、全屏播放器进出、屏幕旋转、日常操作。代码核实：收藏数据在 StationSaveManager 构造时同步装载（SharedPreferences 同步读 JSON），不存在异步空窗；RefreshListGui 有 adapter 空保护，onResume 还有二次刷新。当日异常无法归因到现有代码路径，疑似截图落在转场中间帧或设备偶发状态（如低内存进程恢复），不再按 P0 计。

建议：仍建议接入三态视图：空态插画 + 「去发现电台」引导、错误横幅 + 点击重试、骨架屏——不为复现已知 bug，而为杜绝「静默空白」这类不可诊断的状态。

更正P0-4 原判断不成立：抽屉是「底部导航」的配套备选导航

原判断「抽屉无可达入口、形同虚设」系误读。代码核实（ActivityMain.java #L234-248）：导航模式受设置项「外观 → 底部导航」开关控制——开启底栏时隐藏抽屉（NavigationView GONE + 宽度 0），关闭底栏时才安装 ActionBarDrawerToggle、显示顶栏汉堡并隐藏底栏。两者是互斥的二选一导航，当前真机开启底栏故抽屉不可见，属设计意图而非缺陷。

保留的轻微建议：① 可在该设置项的摘要文案中说明「关闭后改用侧边抽屉导航」，避免用户关闭底栏后找不到导航入口；② 若未来确认不再维护抽屉模式，可再评估移除，但当前不建议。

P1 · 可理解性

P1-1展开卡片 8 个操作图标全部无文字标签

电台卡片展开后的操作行（主页 / 分享 / 收藏 / 闹钟 / 缓冲 / 均衡器 / 转播 / 刷新，共 8 个，部分随电台状态显示）为裸图标——stub_list_item_station_details.xml 中全部为 ImageButton，仅有无障碍 contentDescription，无任何可见文字。其中数个图标语义多义（表盘、滑块），只能靠试错学习。

建议：图标下方补 11sp TextAppearance.RadioDroid.Label 小标签（8 语言同步）；若嫌行高增加，可改为长按弹底部动作表（带文字）。概念图 A 采用标签方案。

P1-2全屏播放器双 Tab 行嵌套，认知负担偏高

顶部「专辑封面 / 信息」+ 中部「本台曲目 / 曲目历史 / 录音」两组页签上下堆叠（分别属于 pagerArtAndInfo 与 pagerHistoryAndRecordings 两个 ViewPager），且滚动时行为不同，用户需要理解两套导航。播放器本应是沉浸界面，此处结构感最弱。

建议：合并为单行四段分段控件「封面 | 信息 | 曲目 | 历史」（见概念图 B），录音入口移入曲目页工具栏；「正在播放 / 台名」常驻顶部不随页签滚动。

P1-3 · 降级网格标签混排导致列基线不齐（原判断部分误读）

部分误读更正：list_item_icon_only_station.xml 中标签已设置 maxLines="2" + ellipsize="end"，不存在原报告所述「换行 2~3 行」；图标-文字间距实为 4dp（space_xs），也不算偏大。真实残留问题只有一项：1 行与 2 行标签的条目混排时行高不一，网格纵向基线不齐（gravity=center 居中加剧了观感跳动）。严重度由 P1 降为 P2。

建议：标签 TextView 固定高度 = 2 行 Caption（minLines=2 或固定高度），使每格文字区等高、基线对齐。

P2 · 质感打磨

P2-1列表卡片垂直间距过小（2dp），密度偏挤

电台卡片上下间距仅 space_xxs 2dp，卡片自身已无描边无投影，间距过小时「浮起感」消失，列表呈一整块；与设置页的大留白形成节奏断层。

建议：卡片间距提升至 space_sm 8dp（改动一个令牌引用），列表呼吸感与卡片层次兼得。

P2-2「旧血统颜色」清理未完成：仍有真实引用点跳出预设体系

核实后的准确结论：跳色风险集中在 2 个仍有引用的 drawable——icon_button_ripple.xml 与 progress_circle.xml 均引用 @color/colorAccent（#1d6293 固定蓝），不随 8 套预设联动。而原报告举例的 snackBarButtonColor #D500F9 与 colorTabUnderline #e0347f 经全库检索并无实际引用（theme 属性 colorTabUnderline 已被样式重定向到预设色，同名色值是死代码），原表述有误导性。

建议：① 将上述 2 个 drawable 改走 ?attr/presetAccentColor 系属性；② 删除无引用的死色值（snackBarButtonColor、colorTabUnderline 等），让「预设 2 槽位派生一切」成为唯一事实。

P2-3字重只有 Regular / Bold 两档，层级过渡生硬

全项目 textStyle 仅有 normal 与 bold；标题直接从 400 跳 700，缺少 Medium(500) / SemiBold(600) 的中间层级，卡片标题、分段标题的重量感区分度低。

建议：在 TextAppearance.RadioDroid.Title / TitleLarge 使用 fontFamily="sans-serif-medium"（500），Bold 仅保留给 Display / Headline 大字；无需引入字体文件即可提升层级质感。

P2-4迷你播放器与底栏的层次关系可再优化

迷你播放条（强调色底）与底栏（卡片面底）之间靠 1dp 分隔线区分，强调色大面积贴底略突兀；播放按钮浅色圆盘在深色播放条上对比强烈但缺过渡（无投影/描边），略显「漂浮」。此条涉及既有确认设计，仅作可选微调。

建议：可选：给播放圆盘加 8%~12% 同色投影或 1dp 深色描边增强「落定感」；迷你条与底栏可尝试统一为卡片面上叠小圆角悬浮条的现代播放器形态（大改，需单独评审）。

七、审查边界说明

以下为已由用户确认的既有设计决策，本报告不将其列为问题、不建议推翻：

  • 「正在播放」高亮：直角方框、2dp 描边、图标间隙 3dp、约 31% 同色遮盖。
  • 大图标模式电台图标 70dp / 行高 88dp；网格图标 72dp；播放器行内小图标 56dp。
  • 全屏播放器播放 / 暂停按钮 72dp；迷你播放器按钮随行高。
  • 电台备注文字：强调色、Caption 字号、无斜体。
  • 暗色主题强调色整体上调一档（300→200 / 200→100）的既有调值。

方法说明：真机截图经 adb 采集（设备 2607d84e，1440×3200）；静态审查覆盖 styles.xml / colors.xml / dimens.xml / layout_main.xml / list_item_station.xml；审计维度（排版层级、色彩与表面、布局、交互状态、组件模式、图标）参照 redesign-existing-projects 方法论，并适配至 Android / Material 语境。

八、复核更正记录（2026-10-13）

应用户要求对报告全部问题逐条对照代码复核，更正如下：

  • P0-4 撤销 — 「抽屉无可达入口」系误读：抽屉是「底部导航」开关关闭时的备选导航（ActivityMain.java #L234-248），开启底栏时隐藏属设计意图，非缺陷；仅保留设置项文案说明的建议。可发现性评分 6.0 → 7.0，综合 7.2 → 7.4。
  • P0-2 改写 — 占位机制在代码中完整存在（StationPlaceholderUtils / Picasso placeholder / 应用图标兜底），「未设计占位」不成立；但实测有图标的电台封面页仍空白，定性改为「占位链路未生效的疑似 bug，待真机复现」。
  • P1-3 降级 — 网格标签已限 maxLines=2，不存在「2~3 行」；间距实为 4dp。仅保留「行高混排致基线不齐」，严重度 P1 → P2。
  • P0-3 精化 — 收藏列表确无三态视图属实；但顶栏 progressBarLoading 存在（服务数据库更新），「全应用零加载反馈」表述修正；异常根因待日志确认。
  • P2-2 举例修正 — 品红 snackBarButtonColor 与玫粉 colorTabUnderline 无实际引用（死值）；真实跳色点是 icon_button_ripple.xml / progress_circle.xml 引用固定 #1d6293。
  • P1-1 数字修正 — 操作按钮实为 8 个（布局中），截图可见 7 个；「无可见文字标签」结论不变。
  • 二次复核（2026-10-13 真机）· P0-2 根因定位，降级 P1 — 依据用户观察「封面播放时才出现」真机复现确认：占位链路正常（播放后图标秒出），缺口在未播放态——updateAlbumArt() 对 getCurrentStation()==null 直接 return，而同屏标题 / 顶栏图标 / 曲目历史用 getCurrentOrLastStation() 照常显示，形成「有信息、无封面」不一致。修复方向明确（回退最后播放电台或空态占位）。
